# App-wide architecture and code audit — 2026-08-20

## Executive result

This pass traced the React/Tauri client, Supabase query boundaries, graph domain types, AI orchestration, proposal/Memory policy, SQL migrations, PostgreSQL tests, and desktop permissions.

The initial audit overcorrected by removing useful deterministic conversation context together with noisy bookkeeping. The compensating migration restores pre-audit Note relationships for explicit user Note-title mentions and approved relationships involving a Note, and also treats an AI-authored Note update as direct discussion evidence. Selected UI context and Memory updates remain excluded. Creation provenance remains independently represented by `produced`.

The app now has a zero-warning lint/type/test gate, one static validated AI tool registry, explicit relationship and engineering contracts, paginated graph reads, shared boundary helpers, a desktop CSP, reduced Tauri permissions, scoped Memory inclusion, and clean production chunking.

This is code-complete locally, not deployment-complete. The new migration and Edge Function have not been deployed in this pass, and PostgreSQL behavior tests could not run because no local Supabase database was listening.

## Scope and method

Inspected:

- frontend Zod schemas, generated database types, Supabase APIs, query keys, and pagination;

## Findings and resolution

### A1 — `discusses` mixed semantics with audit events — high, fixed in code

Previous creation paths:

1. `record_conversation_context` converted exact/fuzzy title mentions and selected UI context into `discusses`.
2. relationship-proposal approval triggers added `discusses` to both endpoints.
3. `resolve_memory_proposal` added `discusses` when an existing Memory changed.
4. `memory_proposal_origin_connection` also added the same Memory-update assertion, making that responsibility redundant.

Why this was wrong:

- A mutation target is not necessarily the subject of substantive discussion.
- Mentions and retrieval traces are evidence-selection facts, not graph semantics.
- The update is already represented by `graph_changes`, `memory_revisions`, `memory_revision_sources`, the proposal, and its AI run.
- `discusses` overlapped `about` unless given a much narrower conversation-specific definition.

Resolution after rollback:

- Selected-node request semantics remain removed, but explicit user Note-title context recording is restored.
- Approved relationship proposals involving Notes again create discussion context; Memory-origin discussion triggers remain removed.
- Memory updates retain revision/audit provenance and create no conversation edge.
- Preserved deterministic `conversation --produced--> new entity` creation provenance.
- Scoped the proposal's `context_assertion_id` lookup to the creation branch, so a later update in the same conversation cannot capture and later undo the Memory's older `produced` assertion.
- Retracted active system assertions generated from raw mentions, selected context, proposal bookkeeping, or Memory updates. User/AI-authored support is preserved.
- Follow-up rollback restores deterministic `discusses` for explicit user Note-title mentions, approved relationships involving Notes, and AI-authored Note updates. All paths reconcile to one assertion per conversation/Note.

Authority: `docs/RELATIONSHIP_CONTRACT.md` and compensating migration `20260821000000_restore_note_update_discussions.sql`.

### A2 — AI tool arguments trusted model JSON too far — high, fixed

The Responses API used strict JSON schemas, but `executeTool` immediately called `JSON.parse` and dispatched unvalidated values. Malformed JSON could abort the entire run, and invalid IDs/bounds/extra fields reached RPC boundaries despite documentation claiming server validation.

Resolution:

- Moved all tool definitions into one registry.
- Runtime validation now uses the exact schema sent to the model.
- UUIDs, enums, lengths, integer/number bounds, arrays, required fields, and additional fields are checked before dispatch.
- Invalid calls return structured tool errors so the model can recover within its bounded loop.

### A3 — Tool availability could drift or become heuristic — high, fixed by invariant

The old tool list was static in practice but embedded in the orchestration file, with no test proving capability invariance.

Resolution:

- Every ordinary reasoning round receives the same complete registry.
- `tool_choice` is explicitly `auto`; the model retains the decision about which typed capability to use.
- Prompt text, embeddings, retrieval output, regexes, and classifiers do not add or remove tools.
- Only the final synthesis round omits tools after the explicit round/call budget is exhausted.
- Tests prove the full registry is returned for ordinary rounds and no unknown read capability is classified.

This preserves model reasoning while keeping authorization, validation, mutation approval, ordering, and resource bounds deterministic on the server.

### A4 — Memory relevance was enforced before model reasoning — high, corrected in follow-up

The initial audit added a semantic cutoff before the model received the top eight ranked Memories. That conflated user-facing retrieval cleanliness with the model's ability to reason across bounded context and caused previously reliable behavioral Memories to disappear.

Resolution:

- Every ranked Memory inside the existing hard bound remains available to the model as untrusted evidence.
- The model judges contextual relevance; retrieval scores rank but do not gate its bounded reasoning context.
- Semantic-only filtering applies only to searched candidates serialized for the user-facing Sources panel.
- The presentation policy is isolated and unit-tested.

This affects evidence inclusion only. It never changes the tool capability surface.

### A5 — no enforceable coding-standard gate — high, fixed

TypeScript strictness existed, but there was no linter and the roadmap still marked linting incomplete.

Resolution:

- Added ESLint flat configuration for TypeScript, React hooks, React refresh, browser/Node/Vitest, and Deno Edge Function globals.
- `npm.cmd run check` now requires zero lint warnings, TypeScript success, and the complete Vitest suite.
- Added `docs/ENGINEERING_STANDARDS.md` for module ownership, AI capability policy, graph semantics, validation, reuse, and handoff honesty.

The new lint gate found and drove fixes for:

- a ref mutated during render in the native conversation context menu;
- effect-derived selection state on Home;
- mobile state modeled with effect/setState instead of `useSyncExternalStore`;
- an internal drag handler that could be overwritten through leaked props;
- missing hook dependencies;
- feature helpers exported from React component modules;
- dead imports and an unused exported layout helper.

### A6 — graph reads silently accepted backend row caps — high, fixed for V1

Home and Graph Lab queried all nodes/edges/assertions once. Supabase/PostgREST row caps could silently produce an incomplete graph.

Resolution:

- Added a tested generic pagination collector.
- Nodes, edges, and active assertions now page until completion with stable secondary ID ordering.
- Retracted/non-active assertions are not downloaded for the live workspace view.

The result is complete but remains an in-memory whole-graph load. That is acceptable for the current personal V1, not an unlimited-scale architecture.

### A7 — repeated infrastructure and unsafe boundary casts — medium, fixed

Resolved duplication:

- three Supabase `unwrap` implementations became one helper;
- repeated date/relative-time logic became one utility;
- graph relationship colors moved into the relationship domain contract;
- raw query-key literals were replaced by a shared key;
- response-ready SSE rows now use their parsed domain type instead of double casts;
- graph adapter logic moved out of the route component;
- AI prompts and tool definitions moved out of the HTTP orchestration entry point.

Memory relationship suggestions now also reject invalid direction/type values and deduplicate identical semantic suggestions before RPC dispatch.

### A8 — oversized entry bundle — medium, fixed

The production build previously emitted an approximately 844 kB minified entry chunk and a Vite warning. Routes were already lazy, but core vendors were still bundled together.

Resolution:

- Added stable React, Supabase, UI, and motion vendor chunks.
- Final entry chunk is approximately 355 kB minified.
- No production chunk exceeds Vite's 500 kB warning threshold.

This is load-boundary work, not semantic module coupling; domain boundaries remain independent of bundler chunks.

### A9 — desktop security was permissive — medium, fixed

The Tauri CSP was disabled and the broad opener plugin/permission was installed despite no call site.

Resolution:

- Added a CSP limited to the app, Tauri IPC/assets, local development, Supabase HTTPS/WebSocket endpoints, and safe image/font/style needs.
- Removed the unused opener plugin, Rust dependency, and capability.
- Retained deep-link and single-instance behavior because they are part of the documented authentication foundation.

### A10 — database contract documentation had drifted — medium, fixed

Documentation claimed Zod specifically validated Edge Function tool calls and described automatic discussion bookkeeping that no longer matches the desired semantics.

Resolution:

- Updated AI protocol and data-model documents.
- Added a relationship contract with exact source→target meaning, automation policy, and non-examples for all eight types.
- Added synchronized frontend relationship contracts and tests.
- Updated pgTAP expectations so automatic discussion triggers/functions are forbidden while creation provenance remains required.

### A11 — search candidates were presented as used sources — medium, fixed in follow-up

Graph and conversation search hits now remain in separate candidate collections until a later tool explicitly loads, traverses, selects, or changes them. All bounded ranked graph candidates remain available to the model; weak semantic-only candidates are filtered only when serializing the user-facing Sources list. Assistant answers can cite used nodes through server-validated, canonicalized `workspace-node:` links rendered as compact pills; the Sources inspector separately presents cited evidence, other used evidence, and sufficiently relevant unused search candidates.

## Relationship independence review

| Type | Independent question it answers | Overlap guard |
| --- | --- | --- |
| `related_to` | Are A and B meaningfully associated when no precise type fits? | Never from similarity or before checking precise types |
| `references` | Does A explicitly point/cite/link to B? | Not merely about or derived from B |
| `about` | Is B a substantial subject of A? | Not a passing mention, provenance event, or citation |
| `part_of` | Is A a constituent contained by B? | Not grouping, order, dependency, or relevance |
| `supports` | Does A provide evidence/material/progress toward B? | Not assertion provenance; assertions support edges |
| `derived_from` | Was A transformed/computed/summarized from B? | Not citation, chat creation, or revision history |
| `discusses` | Does a conversation substantially discuss existing Note B? | Explicit Note-title mention, approved Note relationship, or AI Note update; not retrieval/selected context/Memory revision |
| `produced` | Did a conversation directly create new B? | Creation only; never update or discussion |

The relationship registry answers semantics. Assertion rows answer support/provenance. Audit and revision tables answer operations/history. Response evidence answers retrieval/use. These responsibilities must not be collapsed.

## Architecture assessment after changes

### Strong boundaries

- Graph identity, typed extensions, semantic edges, and independently retractable assertions are correctly separated.
- PostgreSQL remains authoritative for owner isolation, endpoint validity, lifecycle, optimistic concurrency, proposal resolution, and undo.
- Graph Lab retains a backend-free flat data contract and separate adapter.
- TanStack Query owns server state; React local state owns transient UI interactions.
- AI sees typed bounded tools rather than SQL or generic RPC access.
- Retrieval is candidate selection, never durable graph authority.
- Memory extraction is a separate post-turn reviewed workflow with exact source messages.

### Remaining concentration

- `supabase/functions/graph-chat/index.ts` remains a large orchestration module even after tool/prompt/policy extraction. It still combines HTTP/SSE lifecycle, retrieval/embedding refresh, summary refresh, Memory extraction, tool execution, and final persistence.
- `src/features/chat/chat-page.tsx` remains a large UI state machine for network streaming plus progressive visual reveal.
- `src/components/ui/sidebar.tsx` is large but intentionally isolated as a generic/vendor-style primitive; product behavior should not be added there.

Further splitting the first two files is appropriate only with integration coverage for aborts, partial SSE delivery, retries, duplicate events, summary races, and Memory-extraction failure. Line-count-only refactoring would increase risk.

## Security and reliability assessment

- Production npm audit: zero known vulnerabilities at audit time.
- Service-role and OpenAI keys remain server-only; client environment validation allows only Supabase URL and anon key.
- Tool calls, traversal depth, result sizes, rounds, total calls, Memory count, message context, and structured output are bounded.
- Mutation tools remain differentiated between immediate explicit creation and reviewed/reversible substantive changes.
- Node and message content is consistently treated as untrusted evidence in prompts.
- Main-answer completion remains independent from optional Memory extraction, title generation, embedding enrichment, and summary refresh.
- Tauri capabilities are narrower and CSP is enabled.

## Definition of done for the semantic fix

Do not call the `discusses` issue complete merely because this repository builds. Completion requires all of the following against the deployed backend:

- an existing Memory update creates one new revision and exact source rows;
- it creates no new `discusses`, `produced`, or `derived_from` edge;
- undo restores the previous Memory revision and does not affect unrelated assertions;
- a newly approved Memory creates exactly one `produced` system assertion from its conversation;
- an explicit or conservatively typo-resolved Note-title mention creates one `discusses` assertion;
- an approved relationship involving a Note and an AI-authored Note update reconcile to that same conversation/Note assertion;
- retrieval results, selected UI context, unapproved proposals, and Memory updates create no conversation semantic edge;
- existing user/AI-authored `discusses` support survives the cleanup migration;
- old automatic system-only discussion edges archive when their last active assertion is retracted.
